2. ¿Cuáles son las diferencias entre los tipos de datos primitivos y los objetos en Java?
Los tipos primitivos y los objetos resaltan los métodos principales en la forma en que Java maneja los datos básicos frente a las estructuras complejas.

En términos de almacenamiento, los tipos primitivos almacenan valores reales, mientras que los objetos almacenan referencias. Los tipos primitivos ocupan menos memoria, los objetos más. Los tipos primitivos tienen operaciones integradas limitadas, mientras que puedes implementar tantos métodos como quieras para los objetos.

Además, los tipos primitivos no pueden ser nulos, lo que limita su flexibilidad (depende del contexto), mientras que los objetos sí pueden. Por su simplicidad, los tipos primitivos generalmente son más rápidos para acceder y manipular.

En Java, hay 9 tipos primitivos ( intInt, booleanInt, etc.), mientras que puedes crear tipos de objetos ilimitados

4. ¿Cómo se manejan las excepciones en Java?
Las excepciones en Java se pueden manejar elegantemente usando try-catchbloques `with`. En el trybloque `with`, escribimos el código que podría lanzar una excepción, y el catchbloque `with` especifica lo que el código debe hacer si ocurre la excepción.

Un finallybloque `with` se puede usar para operaciones de limpieza si try-catchlos bloques `with` manejan recursos externos como administradores de archivos, conexiones de bases de datos, etc.

Aquí hay un ejemplo de código que demuestra el manejo de excepciones en Java:

import java.io.FileReader;
import java.io.IOException;
public class ExceptionHandlingExample {
   public static void main(String[] args) {
       FileReader reader = null;
       try {
           reader = new FileReader("nonexistent.txt");
           // Code that might throw an exception
           int character = reader.read();
           System.out.println((char) character);
       } catch (IOException e) {
           // Handling the specific exception
           System.out.println("An error occurred while reading the file: " + e.getMessage());
       } finally {
           // Cleanup code that always executes
           if (reader != null) {
               try {
                   reader.close();
               } catch (IOException e) {
                   System.out.println("Error closing file: " + e.getMessage());
               }
           }
       }
   }
}

Aquí hay una implementación segura para subprocesos del patrón Singleton:

public class Singleton {
   private static volatile Singleton instance;
   private Singleton() {}
   public static Singleton getInstance() {
       if (instance == null) {
           synchronized (Singleton.class) {
               if (instance == null) {
                   instance = new Singleton();
               }
           }
       }
       return instance;
   }
}

36. Describa las diferencias entre HashMap, LinkedHashMap y TreeMap.
Aquí hay un resumen de los términos:

HashMap: No ordenado, permite claves y valores nulos, complejidad de tiempo promedio O(1) para operaciones básicas
LinkedHashMap: Mantiene el orden de inserción (o de acceso), permite claves y valores nulos, es ligeramente más lento que HashMap.
TreeMap: Ordenado por claves, no permite claves nulas, complejidad temporal O(log n) para operaciones básicas.

47. ¿Cómo se relaciona el modelo de memoria de Java con la relación de precedencia? Proporcione ejemplos de cómo esto afecta a la programación concurrente.
JMM establece las reglas sobre cómo los programas Java interactúan con la memoria del ordenador, especialmente en entornos multihilo. La relación "sucede antes" es una parte clave de este modelo.

"Sucede antes" garantiza que las operaciones de memoria en un hilo estén ordenadas correctamente con respecto a las operaciones en otro hilo. Esto es crucial para escribir código concurrente correcto.

Por ejemplo, considere la palabra clave volatile :

class SharedData {
   private volatile boolean flag = false;
   private int data = 0;
   void writeData() {
       data = 42;
       flag = true;
   }
   void readData() {
       if (flag) {
           // This is guaranteed to see data = 42
           System.out.println(data);
       }
   }
}
